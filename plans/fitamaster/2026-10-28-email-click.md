# Clickable email sign-in across tabs and browsers

The owner requested opening the email normally in a new tab while keeping mandatory authenticator 2FA. The former PKCE sessionStorage verifier bound email callbacks to the requesting tab; the reported new-tab failure matches that limitation.

Use Supabase's supported browser implicit magic-link flow only in the existing static portal. The email request omits a PKCE challenge and keeps shouldCreateUser:false and the exact canonical redirect. Accept only bounded standard magiclink fragment fields with singleton exact keys; reject mixed/query credentials, errors, provider tokens, recovery/invite/signup callbacks and malformed metadata. Scrub the URL before configuration, SDK initialization or network requests. SDK setSession validates the supplied session against the configured project; the existing server-confirmed owner, live-session and verified-TOTP/AAL2 rules continue to control data requests. Callback rejection must not briefly render an older stored player's data. Sessions stay in sessionStorage; no shared localStorage or application relay of callback credentials is added. The SDK retains its existing Auth event notifications, which do not import another tab's session into this tab's storage. This intentionally allows email-link possession to initiate an AAL1 session in another browser; it grants no admin data access before TOTP.

Scope is frontend Auth setup, callback validation and recovery copy, plus regressions. No database, owner allowlist, Auth provider/template configuration, native app, artwork or other public pages change. Old PKCE links may require a new email; no token migration is attempted.

Verification: observe failing parser/controller regressions first; then targeted and full website suites, deterministic bundle build, independent Auth review and real bundled-SDK browser tests with synthetic HTTP responses. Exercise a separate fresh browser context, exact no-challenge email request, URL scrubbing, TOTP gating/success, enrollment, nonowner denial, expired/rejected/malformed callbacks and storage cleanup. Publish only reviewed changes atop latest main; match the live bundle and verify the public shell. Real mailbox delivery and the owner's private 2FA remain a user acceptance step. Rollback is a revert of this frontend commit; no schema rollback is required.
